# AQNET 코딩테스트 — 광고 매체별 데이터 통합 API와 미니 대시보드

Naver · Meta · Google 광고 데이터를 공통 구조로 정규화하고, 기간·매체별 성과를 반환하는 `GET /api/summary`와 이를 호출하는 웹 대시보드입니다.

## 실행

| 항목 | 내용 |
| --- | --- |
| OS / Node | Windows 11 / Node.js v24.19.0 |
| 설치·빌드 | 없음 (외부 패키지 없음, 오프라인 실행) |
| 실행 | `npm start` |
| 화면 | http://localhost:3000 (성과 요약) · http://localhost:3000/#campaigns (캠페인 실적)<br>API와 같은 서버·포트에서 제공 → CORS·프록시 설정 불필요 |
| 테스트 | `npm test` (44개) |
| 평가 대상 커밋 | (제출 시 기재) |

**PORT, DATA_DIR 변경**

```bash
PORT=4000 DATA_DIR=/path/to/data npm start                  # macOS / Linux / Git Bash
$env:PORT=4000; $env:DATA_DIR="C:\path\to\data"; npm start  # Windows PowerShell
```

- 기본값: `PORT=3000`, `DATA_DIR=./data`. 데이터는 시작 시 한 번 읽으므로 교체 후 재시작합니다.
- 파일 누락·JSON 오류·배열이 아닌 파일은 서버가 **시작되지 않고** 오류 메시지와 함께 종료합니다.

| 항목 | 상태 | 설명 |
| --- | --- | --- |
| 정규화와 데이터 검증 | 완료 | 매체별 필드 매핑, 날짜·ID·실적 숫자 검사, micros → 원 |

| 로딩·오류·빈 결과 | 완료 | 세 상태를 다른 문구로 구분, 오류 시 이전 값 숨김 |

| 선택 심화 | 일부 | 캠페인 상세 API·화면, 테스트 확대 / 캐싱·대량 데이터 측정은 미구현 |

**추가로 만든 화면 기능**: 일별 추이 그래프, 광고비 점유율, 이전 기간 대비 증감률, 빠른 기간 선택(7일·14일·전체), CSV 다운로드, 캠페인 검색·정렬·ROAS 기준 필터, 매체 행 클릭 시 해당 매체 캠페인으로 이동

제공 데이터 처리 결과: 입력 1,260 · 무효 30 · 중복 30 · 유효 1,200

## 설계

**스택 선택 이유**
- 필수 API가 1개라 프레임워크 없이 Node 내장 `http`로 충분하고, 설치 없이 바로 실행됩니다.
- 화면도 일반 HTML/CSS/JS로 같은 서버에서 제공해 실행이 단순합니다. 그래프는 외부 라이브러리 없이 SVG로 그렸습니다.

**구조**

```
src/dataset.js   파일 읽기 → 검증 → 무효 제거 → 중복 제거 (서버 시작 시 1회)
src/summary.js   쿼리 검증 → 필터 → 집계 → 지표 계산 (요청마다)
server.js        HTTP 서버 (API + 화면 파일)
public/          대시보드 화면
tests/           자동 테스트
```

데이터 정리(dataset)와 요청 계산(summary)을 나눠, 정규화는 한 번만 하고 각각 따로 테스트할 수 있게 했습니다.

## 검증

**자동 테스트** (`npm test`, 정답 수치를 하드코딩하지 않고 규칙별 작은 데이터로 검증)

| 위험 | 확인 내용 |
| --- | --- |
| 반올림 | 1.005 → 1.01 (부동소수점 오차 없이 정수 연산) |
| 0 분모 | 광고비 0원이면 ROAS·CPC·CPA가 `null` |
| 합계 기준 | 행별 비율 평균이 아닌 합계로 계산 |
| 중복 | 앞의 무효 행이 뒤의 유효 행을 막지 않음, 값이 달라도 첫 유효 행 유지 |
| 숫자 형식 | `"1e3"`·`"1,000"`·`"+1"`·`true`·`-1`·`1.5` 무효 / `" 120 "`·`"00120"`·`120.0` 허용 |
| 쿼리 오류 | 공백 값, 반복 키, 없는 날짜, start > end, 모르는 매체 → 400 |
| 파일 오류 | 누락·JSON 오류·배열 아님 → 서버 시작 실패 |

**그 외 확인**
- 제공 데이터의 무효 30행·중복 30행을 하나씩 출력해 사유 확인
- 문제지 예시값으로 만든 다른 데이터를 `DATA_DIR`로 지정해 재실행
- 브라우저에서 빈 결과, 400 오류, 서버 중단 시 오류 화면 확인

## 채택한 가정

- 쿼리의 start/end에도 데이터와 같은 날짜 규칙(2000~2099년 실제 날짜)을 적용
- 빈 값이라도 같은 필터 키가 반복되면 400 / platform은 소문자만 허용
- 파일 오류는 "API 500" 대신 "서버 시작 실패" 방식 선택
- 응답에 `dataRange`(데이터 기간), `byDate`(날짜별 합계) 키 추가 (계약상 허용, 화면용)
- ROAS 필터 기준 450% / 350%는 운영 기준 가정 (`public/app.js`의 `ROAS_BANDS`)
- 증감률은 %로, 이미 %인 CTR·ROAS는 %p(차이)로 표시

## 미완성 항목과 원인

- 캐싱·대량 데이터 측정: 필수 기능의 정확도와 예외 처리를 우선해 구현하지 않았습니다.
- 화면 자동 테스트: 저장소에는 없고 브라우저에서 직접 확인했습니다.
