# AQNET 광고 성과 통합 대시보드

Naver · Meta · Google 광고 데이터를 공통 구조로 정규화하고, 기간·매체별 성과를 조회하는 API(`/api/summary`, `/api/campaigns`)와 웹 대시보드입니다.

## 1. 실행 방법

Node.js 20 이상, 외부 패키지 설치 없음.

```bash
npm start   # 서버 실행 → http://localhost:3000  (PORT 환경변수로 포트 변경 가능)
npm test    # 전체 테스트 실행 (node:test)
```

| 확인 대상 | 주소 |
| --- | --- |
| 대시보드 화면 | http://localhost:3000 (성과 요약) / http://localhost:3000/#campaigns (캠페인 실적) |
| 요약 API | http://localhost:3000/api/summary?start=2026-11-01&end=2026-11-02&platform=naver |
| 캠페인 API | http://localhost:3000/api/campaigns |
| 400 예시 | http://localhost:3000/api/summary?platform=kakao |

## 2. 구현 내용

### `src/analytics.js` — 정규화 → 쿼리 검증 → 필터 → 집계 → 정렬

| 단계 | 구현 |
| --- | --- |
| 정규화 | 매체별 필드 매핑을 `MAPPERS`에 모음(매체 추가 시 매퍼 1개만 추가). Meta 문자열 숫자 → `number`, Google `cost_micros / 1,000,000` |
| 쿼리 검증 | `parseQuery()`에서 위반 시 `InvalidQueryError` → `server.js`가 `400 { error: "INVALID_QUERY", message }` 응답 |
| 집계 | 원본 5개 합계를 먼저 구한 뒤 비율 계산(행별 비율 평균 X), 분모 0이면 `null`, 소수 둘째 자리 반올림 |
| 정렬 | `byPlatform`: 매체명 오름차순 / `items`: 광고비 내림차순 → 동점 시 `platform` → `campaignId` |
| 캐시 | 데이터는 서버 시작 시 1회 로드되는 불변 객체이므로 정규화 결과를 `WeakMap`에 캐시 |

### 문제지에 명시되지 않아 직접 정한 규칙

| 상황 | 처리 | 이유 |
| --- | --- | --- |
| 달력에 없는 날짜 (`2026-02-30`) | 400 | 형식만 맞고 실제로 없는 날짜도 잘못된 입력 |
| `start == end` | 허용 | "양쪽 날짜 포함"이므로 하루 조회 |
| `platform=Naver` (대문자) | 400 | 허용 값을 `naver/meta/google`로 명시했으므로 정확히 일치만 허용 |
| `platform=naver&platform=meta` (중복) | 400 | 단일 선택 필터라 의도가 모호한 요청을 거부 |
| `platform=` (빈 값) | 미입력(전체)으로 처리 | HTML 폼의 "전체" 선택 값이 빈 문자열 |
| 숫자로 변환할 수 없는 원본 값 | 500 (데이터 오류) | `0`으로 넘기면 합계가 조용히 틀어지므로 |
| 날짜별로 캠페인명이 다른 경우 | 가장 최근 날짜의 이름 사용 | 최신 명칭이 현재 캠페인을 대표 |
| 반올림 | `round2()`에서 지수 표기 이동(`1.005e2`) | `Math.round(1.005*100)/100 = 1` 부동소수 오차 방지 |

### `public/` — 웹 화면 (바닐라 JS, 외부 라이브러리 없음)

- **필터**: 사이드바의 시작일·종료일·매체 + `조회`·`초기화` 버튼. 매체·날짜 변경 시 즉시 재조회, 조건은 URL에 반영(새로고침·뒤로가기 유지)
- **성과 요약**: 필수 5개(광고비·전환수·매출·CPA·ROAS) 카드 + 보조 지표(노출·클릭·CTR·CVR·CPC), 매체별 광고비 점유율 도넛, 매체별 지표 표(합계 행)
- **캠페인 실적**: 필수 열(매체·캠페인명·광고비·전환수·ROAS) + 노출/클릭·전환 매출, 열 제목 클릭 정렬, 캠페인명·ID 검색, 합계 행
- **상태 처리**: 로딩(스켈레톤·버튼 스피너), 에러(서버 `message` 배너 + 다시 시도), 빈 결과 안내, 연속 조회 시 이전 요청 취소(`AbortController`)
- **보안**: 데이터 문자열은 모두 `textContent`/`createElement`로 렌더링 — `innerHTML` 미사용(XSS 방지)
- **접근성**: 텍스트 대비 WCAG AA 이상, 키보드 조작, 스크린리더용 라벨·표 설명·상태 알림, 색만으로 정보 전달하지 않음(매체명 병기), 고대비·움직임 줄이기 설정 대응
- **환경**: 외부 폰트·CDN 없이 오프라인 동작, 반응형(모바일은 필터가 본문 위로 이동)

### `server.js` (소폭 수정)

- `server`를 export하고 `node server.js`로 직접 실행할 때만 `listen` → 테스트에서 실제 HTTP 400 응답까지 검증하기 위함

## 4. 미완성 항목 / 한계

- **데이터 규모**: 서버 시작 시 JSON을 메모리에 올리는 구조 그대로이며, 대용량 데이터·DB 연동은 고려하지 않았습니다.
- **타임존**: 원본 `YYYY-MM-DD`를 그대로 사용합니다. 매체별 리포트 기준 시간대가 다른 실제 환경에서는 보정이 필요합니다.
- **데이터 오류 처리**: 원본에 숫자가 아닌 값이 하나라도 있으면 요청 전체가 500입니다. 실서비스라면 문제 행만 제외하고 로그를 남기는 정책이 필요합니다.
- **프론트엔드 테스트**: 화면은 헤드리스 브라우저 스크린샷(여러 화면 크기·빈 결과·에러)으로 확인했고, 브라우저 자동화(E2E) 테스트와 실제 스크린리더 테스트는 하지 못했습니다.
- **미구현 기능**: 캠페인 페이지네이션, 기간 프리셋(최근 7일 등), CSV 다운로드, 전기 대비 증감률(이전 기간 데이터가 없어 제외)
